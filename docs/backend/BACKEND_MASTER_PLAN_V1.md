## Auth flows
Google OIDC Authorization Code + PKCE for native/public clients; backend validates issuer, audience, signature via cached JWKS, exp/iat, nonce, state and subject. Google account with Gmail is same Google provider; never treat email domain as authentication. Apple Sign in with Apple via OIDC authorization code and validated identity token, Apple JWKS/issuer/audience/nonce, Apple private relay and name returned only first time. Do not rely on email as immutable identity; key by issuer+sub. For iOS, native SDK generates provider authorization; backend exchanges/validates as designed. Web future: secure BFF/HttpOnly SameSite cookies and CSRF protection, no tokens in localStorage.
Email+password: signup with email verification, Argon2id hashing, minimum length 12 (allow passphrases), block compromised passwords where practical without external network dependence; rate limit and uniform response to unknown accounts. Login and reset via single-use time-limited email link, never disclose account existence.
Magic link: POST request returns generic 202 for all addresses; generate cryptographically random >=128-bit token, persist only hash, TTL 10 minutes, single use, request and redemption rate limits, generic error for expired/invalid. Email link opens app/universal link or local dev callback; avoid leaking token in analytics, referrers, logs, redirect query or browser history; exchange token via POST for short-lived authorization code/session, consume atomically; no auto-login on email link GET (link scanners). Explicit user gesture confirmation on landing screen. Dev mail sandbox via Mailpit and dev-only auth simulator. Provider identities may be linked only from recently authenticated session with reauthentication; prevent unverified email auto-link/account takeover. Unlink last usable login method forbidden.
Sessions: short-lived access JWT or opaque token (document tradeoff; prefer short-lived signed access + rotating opaque hashed refresh); refresh token rotation, reuse detection and family revocation, logout all devices, account deletion. Token audience, scopes and signing key rotation. Sensitive profile reads require account ownership, optional step-up for account deletion. Secure password reset and email change.
Do not implement custom crypto or trust client-supplied role/user_id.

## Safety and domain rules
My Health verified medication plan is authoritative; HealthKit or device data must not silently change dose or schedule. Timezone/DST recurrence must be deterministic; dedupe occurrence IDs; audit schedule edits; no dosing recommendations. Preserve measurement source/provenance and units; avoid automatic cross-unit clinical inference. Explicit consent and export/delete lifecycle. Secure default: profile grants disabled until reviewed. Data deletion must handle derived caches and jobs.

## Sync
Client mutation UUID, actor, resource version, idempotency keys, monotonic server cursor; conflict on schedule edit returns 409 with safe merge metadata (no last-write-wins for medication schedules). Replays idempotent, pagination stable, offline device clocks not trusted for authorization. Sync design must not pre-empt unresolved encryption ADR; implement local-safe development adapter with clear switch and tests; stop only the production-capable sync part at encryption decision boundary, continue all independent local deliverables.
